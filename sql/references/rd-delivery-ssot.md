# rd_delivery 出货 SSOT

公司内网 `oa_report.dbo.rd_delivery` 是出货唯一权威入口，物料属性仍以 `sap_material` 为准。当前为 `pending_schema_upgrade`：旧表还是五列月度汇总，尚未完成完整历史迁移和验收。指定 SSOT 不等于已经切换成功。

目标 rd_delivery 保存最小出货事实：过账日期、完整 PN、数量、单位、运抵国、国家代码，以及文件 SHA-256 / 工作表 / 原行号。来源身份为主键，真实重复业务行保留；规则、文件完成状态和批次回执也放内网。产品分类通过 PN 关联 sap_material，不另建一套人工分类。

首次迁移：备份旧表，检查数据库依赖、Power BI 外部查询和既有写入任务；将已验证的 PostgreSQL 历史导入内网 staging。逐文件指纹、行数、完整行摘要、日期、分单位合计和全部产品线月份核对一致后，由 DBA 切换 rd_delivery。列名兼容不等于明细与旧月度粒度兼容，须发布月度及 PCS 兼容视图，并更新查询适配。

切换后：Excel 原件留作证据 → 本机预检 → 内网固定入口按文件原子提交 → 记录已提交批次 / 发布版本 → 从内网版本更新本机验证副本与 Supabase 查询副本 → 核对归档。重复文件、超时续传依靠来源身份、内容摘要和服务端回执，不按四字段 DISTINCT 或重复累加。

PostgreSQL 历史仅作首次 bootstrap 输入；切换后本机和云端都是内网发布的副本，不独立维护出货事实。副本失败时保留内网已提交状态，重试相同版本，不从陈旧副本反向覆盖内网。权威库恢复另行明确授权。

底层保留全部单位和机壳；默认分析关联当前 sap_material，限定 Z001、排除 Z0090、保留所有国家，按单位汇总。物料维度发生更新时，核对使用同一版本，不能为对上分类统计而修改事实数量。

一次性结构变更、主键调整、依赖检查和表切换由 DBA 执行。运行维护身份执行受控导入，日常查询身份只读，不给 Agent db_owner。当前继续 report_only；旧的本机直接写云端流程不能作为新 SSOT 维护路径。当前查询适配针对旧月度结构，新结构上线前必须适配和实测。
