# 流程与恢复

出货权威目标已指定为 `oa_report.dbo.rd_delivery`，物料权威源仍为 `sap_material`。当前结构升级与历史验收尚未完成，保持 `report_only`。PostgreSQL 历史仅作一次性迁移输入；切换后本机与 Supabase 均由内网已提交版本发布。 下述云端提交阶段仅作为旧协议说明，不用于新 SSOT 入库。副本恢复应先确认对应数据已进入内网权威版本，不能反向覆盖内网。

`target=intranet` 当前为 `report_only`：只读差异报告，不运行下述数据库提交阶段、不归档。原 `cloud` 批次仍绑定原目标，不可通过切换配置改写到内网。

每次使用宿主配置的维护环境运行命令。先 `scan` 查看输入；用户已明确要求入库本批次时可直接 `run`。没有新增文件时返回 `no_new_files`，不创建导入任务或改写数据库。仅有已完成文件的相同指纹时返回 `only_duplicates`，保留输入副本并报告跳过；不自动删除用户文件。

## 阶段

| 日志 phase | 已完成 | 后续动作 |
|---|---|---|
| prepared | ZIP 备份、字段/类型/筛选检查、固定 JSON 载荷 | 在本机事务内执行完整导入并 ROLLBACK |
| local_validated | 本机预演、逐行摘要和数量验证 | 生成 pg_dump 备份、检查归档目录，提交本机事务 |
| local_committed | 本机已提交，云端尚未全部确认 | 调用固定员工 HTTPS RPC，逐文件原子提交 |
| cloud_synced | 云端来源摘要与本机预演一致 | 再查双端基线及涉及月份的全部产品线/单位 |
| verified | 双端完整核对通过 | 验证原件指纹，移动归档、更新台账 |
| archived | 归档及台账完成 | 同一批次再运行返回 already_complete |

实际日志和业务数量只保存在批次目录。不可根据文件是否存在、HTTP 超时或本地写入成功推断云端完成。

## 重试与停止

- 连接中断/超时：使用 `resume --batch <原目录>`。请求可能已在云端提交，服务器会验证同一指纹与摘要后返回零新增，不能换文件名重新开批次。
- 同名文件指纹不同：按修订处理，暂停。追加 Skill 不删除/替换历史，需要另行核对并获得明确替换授权。
- 整份业务行多重集合相同：暂停为疑似重复。Excel ZIP 元数据变化、行排序变化不能成为重复入库依据。
- 部分业务键匹配：可能是跨文件重叠，也可能是同日同量的真实独立交付。保留证据并核对业务来源；无稳定交付单号时不能声称已经自动去重。只有用户确认独立后才记录具体 overlap_review，保留原行。
- 未匹配 PN/物料摘要不同：暂停，先通过既有物料同步流程更新并核对两端。不能修改 PN、临时放宽 SSOT 或让分析视图静默忽略该数据。
- 数据库备份失败、载荷/来源 ZIP 被改动、未知日志阶段或历史基线不同：暂停，不继续写入或自动修复。
- preparing/preparation_failed：尚未完成载荷准备，不可 resume。保留来源 ZIP 和报错，修复原件后重新 prepare；这一阶段没有数据库写入。
- 归档时原件被编辑/移动：数据库批次保留，来源 ZIP 保留。先核对变更，不能把不同字节的工作簿当成已导入原件。
- 锁目录遗留：先核对 owner.json 的进程确已退出，再清理该锁；不能按时间自动抢占仍在运行的任务。

单文件最多接收选中行和载荷的有界大小，超限则要求另行审核的大文件流程，不部分提交一半文件。当前规则对 Z001 数量要求整数，其他单位保留精确十进制；所有汇总按单位分组。原 Excel 不改写，来源行号用于恢复与核对。

维护不包含定时任务或自动全量物料刷新。跨库没有原子提交承诺；失败时保留明确阶段，通过同批次幂等续传恢复。
